# Vitium reporter UX baseline (2026-10-08)

**Recorded at:** commit `bba1d59` (main), before any Phase E / VIT-UX change on branch `p0/forma-ux`.
**Method:** I read `site/index.html`, `site/app.mjs`, `site/submission.mjs`, `site/public-config.mjs` and `site/styles.css`. `npm test` was 38/38 passing. No browser was run (Playwright belongs to the verification agent), so the behaviour below comes from the source and is **not browser-witnessed**.
**Purpose:** make regressions checkable. Any later change to the legacy GitHub path must keep every item marked **[keep]**, or record an explicit decision.

## 1. Configuration in effect

- `site/public-config.mjs` has `enabled: false`, `endpoint: ""` and `turnstileSiteKey: ""`. So `privateConfigured === false`, and **only the legacy GitHub handoff is reachable**. [keep]
- Forma comes from `https://cdn.jsdelivr.net/npm/@echelon-foundry/design-system@0.3.0/dist/all.css`, with an exact version in the URL and no `integrity` attribute.
- The CSP meta allows `style-src` jsdelivr and challenges.cloudflare.com, `connect-src 'self'` plus the intake host, and `form-action https://github.com`.
- Canonical: `<link rel="canonical" href="https://vitium.echelonfoundry.com/">` and `og:url` with the same value. No github.io references. [keep]

## 2. Visible states (legacy path)

| State | What is visible | Progress text (`#progress`) |
|---|---|---|
| Draft | `#defect-form`. `#review`, `#private-success` and `#feedback` are hidden. `#github-foot` is visible. | `Step 1 of 2 · Describe the problem` |
| Draft + error | Same as Draft, plus `#feedback` (role=alert) with the message, which receives focus | unchanged |
| Review (handoff ready) | `#review` with the `#github-destination` note and `#submit-link` (an anchor to the GitHub prefilled URL, `target=_blank`). The form is hidden but **keeps its values**. | `Step 2 of 2 · Review your report` |

There is no "submitted" state on the legacy path. The page never claims submission: the review note says "You must sign in to GitHub and select **Submit new issue** there to finish. The report is not yet submitted." [keep]

## 4. Validation and messages

1. Native constraint validation (`form.reportValidity()`) runs first. Browser bubbles appear on the first invalid control. Custom code shows nothing in this case, and focus goes to whatever the browser chooses.
2. Then `normalizeReport` (throws on the first error) shows **one** message in `#feedback` and focuses it. Messages: `Please select the affected application.`, `Please select how the defect affects you.`, `Please enter a short summary.` / `what happened` / `what you expected`, `<Label> must be N characters or less.`, `The page URL is too long.`, `Enter a valid page URL or leave it blank.`, `The page URL must start with http or https.`, `Please confirm you removed passwords and private information.`
3. `buildIssueUrl` throws `This report is too long for GitHub's submission link. Shorten the description or steps to continue.` when the encoded URL is over 7500 characters. The message shows in `#feedback` and the form stays visible with its contents. [keep]
4. Errors are **not** linked to fields: there is no `aria-invalid` and no `aria-describedby`, and no error summary lists every invalid field.

## 5. Focus behaviour

- Review → focus `#review` (the section, `tabindex=-1`), not its heading.
- Edit → focus `#title`. The form is unhidden **with its values intact**. The in-memory draft and requestId are cleared.
- Error → focus `#feedback`.
- There is no polite live region: progress text changes are not announced.

## 6. Legacy GitHub handoff contract [keep exactly]

- The URL is `https://github.com/kemiller2002/vitium/issues/new?title=[<product>] <title>&body=<formatIssueBody>`.
- The body contains `<!-- vitium-report:v1; product=…; impact=… -->`, quoted multiline sections, `_Not provided_` for empty optional fields, and the closing disclaimer line.
- `pageUrl` is reduced to `origin + pathname` (credentials, query and fragment are stripped).
- The page opens GitHub in a new tab (`target=_blank rel="noopener noreferrer"`). The user must click **Submit new issue** on GitHub. Vitium never shows a submitted or received state for this path.
- No draft persistence (no storage APIs).

## 7. Private path (present but unreachable)

When enabled with a valid endpoint and site key, the code would: swap copy and footers, load Turnstile, then POST JSON with an `Idempotency-Key` and show `#private-success` with `#report-reference` only when `status === "received"` and the reference matches `^VIT-[A-Za-z0-9-]{8,}$`. Defects found by reading:

- The request body omits `schemaVersion: "1.0"`. The server (`service/report-domain.mjs`) rejects that with `invalid_input` 400, **so every private submission would fail**.
- The server's typed `code` is ignored. The client shows the server's `message` verbatim, so there's no mapping to actionable guidance and no distinction between retryable and final errors.
- A new `requestId` is generated on every review. Retry after an error reuses it correctly, but Edit → Review creates a new one, as intended. A timeout or network failure is reported as an ordinary error even though the outcome is unknown.
- The success copy says "durably received". That is acceptable only after the server ack, which the code does wait for.

## 8. Layout

- Two-column grid above 900px and one column below. Below 580px the review actions stack.
- `.report-preview dd` uses `overflow-wrap:anywhere; white-space:pre-wrap`. Inputs are `width:100%; min-width:0`.
- `.nav-link` has `white-space:nowrap` on desktop and wraps under 580px.
- `prefers-reduced-motion`: transitions are applied only under `no-preference`.
- `forced-colors` adjustments exist.
- Colour is not the only state signal: errors also carry text.
